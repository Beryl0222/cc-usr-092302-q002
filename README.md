# 县域心血管影像联动与转诊服务

面向县域心血管筛查场景：基层机构（乡镇卫生院等）完成心电 / 心脏 CT / 冠脉造影采集，
富平县医院等中心判读并回传报告，需要时向上级介入中心转诊。本仓库在基线事件信封
（`event_id / kind / occurred_at / subject_id / version`）之上，实现影像联动与转诊
的领域服务、事件存储与读模型，全部以仅追加事件留痕。

## 模块

| 文件 | 职责 |
| --- | --- |
| `src/kinds.js` | 事件类型、模态、四条责任链、角色、风险/紧急级别、转诊目的与最小披露清单 |
| `src/store.js` | 仅追加事件存储：幂等去重、物理版本与临床顺序双轨 |
| `src/envelope.js` | 事件信封校验（兼容基线 `src/contract.js`） |
| `src/service.js` | 领域服务：全部业务命令与规则，违例抛 `DomainError` 且不落任何事件 |
| `src/projections.js` | 读模型：病例状态、机构队列、患者视图、转诊还原时间线、披露台账 |
| `src/index.js` | 统一导出 |

## 核心设计

### 1. 双轨版本顺序（断网补传 / 重复上传 / 专家更正）

- **物理版本 `version`**：事件到达系统时按落库顺序单调分配，永不改变，供审计引用。
- **临床顺序**：重放时按 `(occurred_at, local_seq, version)` 排序。基层断网期间现场
  已发生的影像与判读，恢复后以 `connectivity: "BACKFILL"` 补传，虽晚到仍回到其发生
  时刻应在的位置，事件带 `backfill` 与晚到标记。
- **重复上传**：幂等键按病例隔离（`病例:upload_id`），网络重试只生效一次；不同批次
  携带相同 `checksum` 的影像被识别为重复（`IMAGE_UPLOAD_DEDUPLICATED`），不产生新索引。
- **专家更正**：只追加 `INTERPRETATION_CORRECTED`，原意见完整保留，新版本记录
  `supersedesEventId` 与更正原因。

### 2. 四条责任链互不混用

| 场景 | 初判 | 补充 | 签署 |
| --- | --- | --- | --- |
| 低危筛查 `LOW_RISK_SCREENING` | 中心判读医师 | — | 基层临床医生 |
| 无症状高危识别 `ASYMPTOMATIC_HIGH_RISK` | 心血管专科专家 | 中心判读医师 | 基层临床医生（**须先风险分层**） |
| 术前测量 `PREOP_MEASUREMENT` | 心脏影像专家 | 中心判读医师 | 基层 / 接收临床医生 |
| CT-FFR 补充判断 `CT_FFR_SUPPLEMENT` | 心脏影像专家 | CT-FFR 分析员等 | 基层临床医生 |

- 越权初判、跨链出具 CT-FFR 意见均被拒绝。
- **任何影像建议都不能替代临床医生签署**：判读 / 补充 / 更正事件带 `advice_only`，
  转诊必须存在 `CLINICAL_DECISION_SIGNED`；影像角色出现在签署人名单中即被拒。
- 急症时间窗：判读未达时允许临床医生凭 `clinical_basis`（床旁心电图等纯临床依据）
  先行签署、先转诊，资料后补，避免等待补充资料错过窗口。

### 3. 危急信号只升级相关患者

`CRITICAL_SIGNAL_RAISED` 是病例级事件。机构队列 `institutionQueue` 仅把该患者置顶、
计数并携带升级对象，同机构其他患者照常推进（判读、签署、转诊不被冻结），处置落定后
危急闭环。

### 4. 最小披露、授权撤回与可追溯留痕

- 转诊目的（急症救治 / 专科会诊 / 术前规划 / 补充分析）各自绑定允许披露段落
  （`PURPOSE_SECTIONS`）。授权超出目的范围直接拒绝；实际披露只含「目的允许 ∩ 患者授权
  ∩ 当前已可得」的资料，急症缺失段落进入 `pending_sections`，到达后增量补充披露。
- **交接前**撤回授权：发出 `CONSENT_WITHDRAWN` + `SHARING_REVOKED`，停止后续共享；
  **交接后**（`REFERRAL_HANDED_OVER`，资料已进入诊疗病历）撤回只留撤回痕迹，不撤销
  已入病历的决定，台账显示「已进入病历，撤回仅留痕」。
- 回执 `RECEIPT_ISSUED` 只能确认实际已披露的段落，虚列段落会被过滤。

### 5. 一次转诊可完整还原，预约信息以接收方为准

- `referralTimeline(caseId, referralId)` 还原：检查申请 → 设备/协议版本 → 影像索引
  （含检查阶段）→ 结构化判读 → 补充/更正 → 风险分层 → 签署 → 授权 → 最小披露包 →
  回执 → 接收确认/预约 → 交接 → 最终处置，并标明补传晚到事件。
- 患者视图中的预约时间、地点状态与联系人**只能由接收机构**写入；基层不能代发，
  接收方改约产生带 `update` 的新确认，拒收则预约与联系人清空并展示拒收原因。
